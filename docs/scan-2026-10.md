# OHPM 生态质量扫描 · 2026-10

用 `ohpm-lint` 扫描 OHPM 中心仓 `popularity` 排名前 60 的包，记录真实上架包与官方规范之间的差距。

- **时点**：2026-10-21
- **样本**：60 个包（48 个规范 HAR + 12 个 npm 风格包）
- **工具**：`@quizzyjoy/ohpm-lint@0.2.0`
- **口径**：官方写明「会导致上架失败」→ `error`；官方仅「建议」→ `warn`

## 复现

```bash
npm run build
node scripts/scan-ohpm.mjs --out scan.json <包名...>
```

## 总览

| 指标 | 数值 |
|---|---|
| 样本 | 60 |
| 规范 HAR（含 `oh-package.json5`） | 48 |
| npm 风格包（仅 `package.json`） | 12 |
| 规范包 error / warn / info | **8 / 217 / 47** |
| 平均 warn / 包 | **4.52** |
| 零告警包 | **0** |
| warn 分布 | 1–3 条：15 · 4–6 条：25 · 7+ 条：8 |

> 12 个 npm 风格包（`pako`、`dayjs`、`rxjs` 等）中心仓允许直发，但没有 `oh-package.json5`，HAR 规范对其不适用，因此单独归类（`OHPM-PKG-01`）。

| 问题 | 次数 |

| 开源包缺 `repository` | 6 |

## 其他

- **license 写法**：15/48（31%）不是 SPDX 标识（`Apache License 2.0`、`MIT License`、`LGPLv2.1 or later`…）。
- **体积**：p50 **0.30 MB**、p90 **19.0 MB**、max **76.3 MB**（`@rnoh/react-native-openharmony`）。
- **`nativeComponents` 一致性**：16 个包（33%）的声明与实际 `.so` 对不上（常见是漏声明 `libc++_shared.so`）。

## 扫描过程中修正的误报

把工具对着真实数据跑，第一版报出 30+ error，逐条核对 HAR 后确认大部分是工具的错。已修正并加入测试：

| 现象 | 真相 | 修正 |
|---|---|---|
| `author` 是字符串报 error | 8 个已上架包都这么写 | 降为 warn |
| 兼容 SDK「未填写」 | hvigor 有时写数字 `12` | 接受 `string \| number` |
| 声明的 `.so` 不存在 | 实际在 `libs/arm64-v8a/` | 按 basename 比对 |
| 源码泄漏 | 源码 HAR 本来就带源码 | 仅对声明混淆/字节码且含非 `.d.*` 源码的包告警 |
| npm 包「缺四件套」 | 中心仓允许 npm 包直发 | 新增 `OHPM-PKG-01`（info），跳过 HAR 规范 |
| 安装命令不匹配 | README 写的是 `ohpm install pkg@1.2.3` | 比对前剥离 `@版本` |
| 敏感文件 error | 命中第三方测试证书 | `src/` 下降为 warn |
| `.so` 不在 `libs/` | 源码 HAR 的 `src/main/cpp/prebuilt/` 是构建输入 | `src/` 下不再报 |

原则：**lint 应该对齐「能不能过审」，而不是对齐文档字面**。

## 局限

1. 样本是热门包，不代表 4453 个包的整体分布（长尾只会更差）。
2. README 检测是关键词级，能发现「整节缺失」，发现不了「写了但写错」。
3. `SIZE-05` 是质量建议（官方硬限 500 MB）。
4. 审核口径来自 2026-10-21 抓取的官方帮助中心，平台随时可能调整。
